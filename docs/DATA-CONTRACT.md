# 数据操作契约

> 状态：已确认，作为工程与数据层的实现依据。视觉与交互见 [VISUAL-SPEC.md](./VISUAL-SPEC.md)。
> 本契约定义规范，不作为实现完成清单。当前代码为 Dexie 数据库版本 3、JSON 备份版本 1；§11 描述已实现基础层与尚未接入的提供方边界。实现状态见 [TASKS.md](./TASKS.md)，验证范围见 [VERIFICATION.md](./VERIFICATION.md)。

## 1. 数据实体

### 1.1 快捷方式（shortcut）

| 字段 | 说明 |
|---|---|
| id | 稳定唯一标识，创建后不变；用于排序、引用与未来同步 |
| groupId | 所属分组标识 |
| title | 普通文本标题，≤80 字素簇 |
| url | 已校验并规范化的 http/https 地址 |
| icon | 图标引用（文字首字母 / 六种内置图形 ID / 本地资源 id） |
| iconSourceUrl | 可选，外链下载的来源 URL；随备份导出 |
| order | 组内排序位置 |

### 1.2 分组（group）

| 字段 | 说明 |
|---|---|
| id | 稳定唯一标识 |
| name | ≤40 字素簇，允许重名 |
| colorRole | 语义色角色（primary / secondary / tertiary 等）或空 = 自动分配 |
| order | 全局分组顺序 |
| isDefault | 系统默认分组角色；同一时刻有且仅有一个 |

### 1.3 设置（settings）

- 外观：主题模式、背景引用、动态色开关、配色模式与手动种子色、照片遮罩强度。
- 搜索：默认引擎引用与自定义引擎列表。联网搜索建议不属于 MVP，未来重启该功能前须先确认服务和外发查询授权。
- 布局：`order` 顺序数组与 `hidden` 隐藏集合（见 §4）。
- 时钟：`follow-system` / `12h` / `24h` 三态。

### 1.4 资源（asset）

图标与背景的本地二进制，记录 kind、尺寸、最终 MIME 与可选来源 URL。结构化配置只保存引用，不内联二进制。

## 2. 校验规则

### 2.1 地址（url）

- 仅接受 `http:` 与 `https:`；拒绝 `javascript:`、`data:`、`file:` 等。
- 去除首尾空白；缺少 scheme 时补 `https://`。
- 解析后要求：协议为 http/https、存在主机名、不含用户名或密码。
- 保留路径、查询参数与片段，不改写用户输入。
- 长度 ≤2048 个 Unicode 字符。

### 2.2 名称

- 标题 ≤80 字素簇、分组名与引擎名 ≤40 字素簇。
- 去除首尾空白，拒绝空值与控制字符；按 Unicode 字素簇计数。
- 普通文本，不支持 HTML 或 Markdown；允许重名，以 id 区分。

### 2.3 重复地址

允许完全重复的地址，同组或跨组均可；每条独立记录、独立标题与图标，不做隐式合并或去重。

### 2.4 搜索引擎

- 内置引擎只可选择，不可编辑或删除；默认指向 Google。
- 自定义引擎可增删改，仅接受 HTTPS 模板。
- 模板必须恰好包含一个 `{query}`，且只能出现在查询参数的值中（不得出现在协议、主机或路径里）；提交时对查询内容做 URL 编码。
- 删除当前默认引擎前必须先指定另一个有效引擎；不允许删除最后一个可用引擎。

### 2.5 颜色

- 颜色一律保存为小写 `#rrggbb`；不接受三位简写、`rgb()` / `hsl()` 写法或带透明度的值。
- 取色面板内部的 HSV、色相与滑块位置都是界面状态，不落库：写回的始终是 `#rrggbb`。
- 屏幕吸管返回的 `sRGBHex` 在写入前同样规范成小写 `#rrggbb`。
- 十六进制输入在构成合法颜色前不写入；非法输入只标记该输入无效，不回滚用户已选定的颜色，也不清空设置。

## 3. 分组生命周期

- 任何状态下至少存在一个分组；系统默认分组可改名但不可删除。
- 删除其他分组需二次确认，对话框显示分组名与站内网站数量，确认后连同组内网站永久删除，不提供整组撤销。
- 新建分组追加到末尾，可通过上移/下移调整，重命名不改变顺序。
- 分组颜色使用语义色角色；默认分组使用 primary，新组按主题色板自动分配，可后续更改。
- 导入文件若缺少分组或缺少默认分组角色，整份拒绝，不自动修复。

## 4. 布局插槽模型

- 固定三个命名区域：`clock`、`search`、`shortcuts`（分组标签与网站网格同属 shortcuts）。
- 持久化为 `order: string[]` 与 `hidden: string[]`，只能包含上述已知标识，不允许重复或未知标识。
- 插槽布局设置面板提供区域显示开关与上移/下移；不提供插槽拖拽、任意坐标、尺寸或嵌套布局。主页的网站/分组编辑模式仍支持拖动排序。
- 设置入口不属于可隐藏区域；三个区域全部隐藏时仍保留入口与恢复提示。

## 5. 图片与资源规则

### 5.1 可接受格式

JPEG、PNG、WebP，以及受限静态 SVG。SVG 只在满足安全子集时被接受，并在本地栅格化。

### 5.2 安全 SVG 子集

- 必须为静态 SVG：拒绝脚本、`foreignObject`、事件属性、外部引用/字体、CSS `url()` 与外部样式表。
- 原文件 ≤10 MiB，转换输出 ≤1024×1024 且 ≤4 MP。
- 在本地画布栅格化为 PNG；无法可靠安全转换时明确报错，提示改用 PNG/WebP。

### 5.3 尺寸与体积

| 类别 | 原文件 | 像素 | 输出 |
|---|---|---|---|
| 用户照片背景 | ≤10 MiB | ≤40 MP | 最长边 ≤2560 px，输出 JPEG/WebP（安全静态 SVG 与静态 PNG 也栅格化为 PNG） |
| 网站图标 | ≤10 MiB | ≤4 MP | 最长边 ≤1024 px，统一静态 PNG |

- 动画 WebP 取第一帧并转静态 PNG。
- 本地上传的 SVG 与外链 SVG 采用同一安全处理。
- 本地自定义图片（背景 + 图标）总量 ≤50 MiB。

### 5.4 图标来源

四类：文字/首字母、内置基础图形、本地上传、图片直链下载到本地。不按网站地址自动抓取 favicon，渲染时不加载远程图标。

### 5.5 图标直链下载

- Dashboard Icons 可作为用户参考的外链，不内置其目录、不调用其接口；用户粘贴最终图片直链。
- 接受任意公网 HTTPS 主机；HTTP 仅允许主机名严格等于 `localhost`。
- 拒绝明显本机/回环 IP 与内网主机名（尽力校验，见 §9 限制），并拒绝所有重定向，要求用户粘贴最终直链。
- 拒绝含用户名或密码的 URL；保留查询参数，下载前提示来源 URL 会保存到本机与备份。
- Manifest 声明 `optional_host_permissions`（`https://*/*`、`http://localhost/*`），仅在用户点击下载时对具体来源调用权限请求；只请求当前主机，不安装时授予全部站点访问。
- 用户取消或拒绝权限即不下载；失败或 CORS 不允许时保留当前图标并提示改用本地上传，不退化为后台代理。
- 下载成功后本地化保存；来源 URL 写入记录，界面可提供来源链接，不保存许可字段。

### 5.6 资源清理

- 按引用关系清理：不再被任何记录引用的图片及其来源元数据一并删除。
- 手动仅清除来源时只删元数据，保留已下载的本地 PNG。

## 6. 备份格式与流程

### 6.1 内容

- 版本号、导出时间、分组、快捷方式、设置（外观/搜索/布局/时钟）、自定义引擎。
- 图片以 base64 内嵌，外链图标的来源 URL 随图记录。
- 不包含：浏览器站点权限、临时界面状态。
- 同步元数据、恢复密钥、CryptoKey 与提供方凭据不进入普通 JSON 备份。

### 6.2 上限

- JSON 文件 ≤70 MiB；解码后图片资源总量 ≤50 MiB。
- 数量上限：≤50 个分组、≤1000 个快捷方式、≤20 个自定义引擎；用户新增与导入统一执行。

### 6.3 导出

- 单事务读取生成自包含 JSON；超过任一上限则中止并说明（首版不支持分包）。
- 不自动压缩或降质以强行导出。

### 6.4 导入

- 完整替换：先展示汇总概览（分组数、网站数、图片数、主题与引擎），再二次确认。
- 先完整校验整份文件，再以单一事务替换；任一错误（未知新版本、非法地址、超限、结构损坏、未知字段）拒绝整份文件，现有数据保持不变。
- 当前只接受 JSON 备份版本 1；没有声明支持的旧 JSON 格式或备份迁移器。未知版本拒绝，不降级导入。IndexedDB 数据库版本与 JSON 备份版本独立。
- 不根据来源 URL 重新下载图片，只恢复内嵌图片与来源记录。
- 站点权限不随备份恢复，导入不能授予浏览器权限。已配置同步时，完整替换给旧实体生成墓碑；已登记过的导入 ID 与引用一起更换，详见 SYNC-PROTOCOL.md。

## 7. 编辑、删除与重置

- 字段编辑（标题、地址、名称、模板）采用草稿态 + 显式保存；取消不改原数据。
- 网站与分组的增删改排序入口都在主页：右键对象（或编辑模式下的「⋯」）打开操作菜单，编辑模式下可拖动排序。拖动与菜单里的上移/下移（分组为左移/右移）写入同一个位置字段，结果一致。
- 分组改名在对话框中完成；删除分组仍需二次确认并显示组内网站数量。
- 排序（分组顺序、组内顺序、上/下移）立即保存；存储失败时保留原顺序并明确提示，不显示假成功。
- 单条删除立即保存，并在当前页面会话内提供 5 秒撤销；关闭页面后删除即生效，撤销状态不跨会话持久化。
- 分组删除为二次确认的永久操作，不可撤销。
- 重置本地数据：二次确认后清空用户数据并恢复默认（空默认分组、中性渐变、跟随系统、默认引擎），不删除扩展，也不清除浏览器已授予的权限。

## 8. 搜索建议（MVP 不提供）

MVP 不请求联网建议，不存储查询历史；只在用户提交时打开所选搜索引擎。重新纳入该功能需要重新确定服务、外发查询授权与密钥方案，依据见 [DECISIONS.md](./DECISIONS.md)。

## 9. 已知限制（如实记录）

- Manifest V3 扩展无法可靠判断任意域名最终解析出的 IP，故“拒绝内网地址”只能尽力校验，无法绝对排除私有 DNS 映射。
- 扩展无法直接读取操作系统壁纸或系统强调色；动态取色的来源是扩展自身当前背景。
- 联网搜索建议按产品决策排除在 MVP 外；只有重新决定纳入时，才启动服务与权限核验。
- 屏幕吸管依赖 `EyeDropper` API（仅 Chromium 系提供）。界面按能力探测决定是否显示入口，但**取色结果尚未在真实屏幕上人工验证过**，自动化测试只覆盖了能力探测、用户取消与其他失败的分类。
- 颜色只保存 `#rrggbb`，色相不单独存储：当饱和度为 0 或明度为 0 时，色相无法从颜色本身还原，重新打开取色面板时色相由颜色反推。面板展开期间会保留用户当前色相，收起再打开则会归零。

## 10. 默认值

| 事项 | 默认 |
|---|---|
| 初始分组 | 一个空的默认分组（可改名，不可删除），无预置网站 |
| 时钟 | 跟随系统区域设置 |
| 搜索引擎 | Google |
| 搜索建议 | MVP 不提供 |
| 主题 | 跟随系统 |
| 动态色 | 开启，跟随当前背景 |
| 背景 | 中性渐变；照片由用户上传或主动下载 |
| 图标 | 文字/首字母 |
| 布局 | `clock` → `search` → `shortcuts`，全部显示 |

## 11. 跨设备同步（基础层与手动协调已实现，提供方未接入）

- 同步分组、快捷方式、设置、照片和图标；保持现有 UUID，不将图片 Blob 放入结构化记录。
- Dexie 是本地工作数据源。Google Drive appDataFolder 或 HTTPS WebDAV 保存加密的每设备完整快照和独立媒体对象；一个同步库一次只使用一个提供方。Chrome storage.sync 不承载数据。
- 同步状态、设备身份、字段级逻辑版本、删除墓碑和本地 CryptoKey 存放在独立 Dexie 表，不进入用户可见领域记录或普通 JSON 备份。
- 字段级冲突以 Lamport 逻辑时钟及设备 ID 确定胜者；同 ID 删除墓碑优先且 ID 不复用。位置合并后确定性排序并重新编号。
- 云端快照与媒体统一 AES-256-GCM 加密。恢复密钥为本地随机生成的 256-bit 密钥，用户保存并手动带到新设备；密钥和提供方凭据不上传。
- 首次连接先合并，不静默覆盖本地用户数据。无效远端数据不得部分应用；候选和媒体完整校验后，通过单一 IndexedDB 事务提交。随后发布失败保留完整本机合并和新编辑，明确失败/待同步，不伪造跨本机与远端的原子回滚。
- sync_state 的本机基线、运行 ID/阶段/发布确认和最近成功记录不进入快照或 JSON 备份。完整接收后记住首次合并基线，即使发布失败也不重复提升旧字段；断开/重连后的旧运行不改新连接状态。
- 用户未启用同步时，扩展不连接同步服务。启用后异步同步不阻塞新标签页本地渲染；无定时轮询。
- 基础协议见 [SYNC-PROTOCOL.md](./SYNC-PROTOCOL.md)，公共端口、先本机接收/先媒体后快照与失败恢复见 [SYNC-COORDINATOR.md](./SYNC-COORDINATOR.md)。连接界面、自动调度和提供方仍未实现；设备集合、远端清理及密钥轮换需继续实施。
