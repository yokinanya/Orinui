公共 downloader 逐跳使用 redirect:error、omit credentials/no-referrer；临时读取 Location 并校验目标，同来源继续，跨来源交回界面显示目标，等待新的点击和来源权限。每一跳按去 fragment 的网络 URL 使用原生独占锁，监听结束后移除，非法目标/缺少 Location/循环/网络/HTTP/解码/清理错误明确显示。新增 11 项平台测试及 1 项照片令牌测试，当前单测 290 项。

最终生产 UI 的隔离 Chromium 153.0.8010.12 检查通过：301→302→PNG 完整下载；跨来源确认前目标请求数 0、确认后 1；fragment 循环失败且当前图标保留；用户给出的 jsDelivr 哔哩哔哩链接实际下载、解码、保存及刷新本地还原。该链接本轮真实响应是 200，原先 CDN 返回 301 的具体 Location 未复现；受控 301/302 链单独验证。仅审计副本预先授予 webRequest 和 localhost/jsDelivr 权限，生产 manifest 仍为可选权限；本次未验证用户实际看到的授权/拒绝/撤销弹窗。

正式核心 downloader 的原生审计还验证了同 URL 并发与不同入口汇合到同 URL 的逐跳串行，服务端并发峰值 1；私网/跨来源未确认目标请求数均为 0。最终 UI 报告 `.output/ui-download-audit-result.json` status=passed；底层审计在 `.output/redirect-audit/result.json`。这些是本机忽略的验证产物。
