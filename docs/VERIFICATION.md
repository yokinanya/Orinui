### 坚果云无 ETag 兼容模式（2026-10-14）

用户确认坚果云的 PUT 响应、`DAV:getetag` 与 GET 均无法提供有效强 ETag。先前只补查 GET ETag 的严格模式复验仍失败，因此默认坚果云模板现在使用单独的 `readback-only` 模式：以加密对象字节的 SHA-256 作为 revision，发布快照前读取并比较预期摘要，PUT 后读取并逐字节核对；媒体先检查是否已存在，创建后同样核验。连接探测执行唯一对象的 PUT、GET、DELETE 与删除后确认，不再伪测 ETag 条件能力。

模式跟随模板写入本机 WebDAV 配置 schema 2；schema 1 旧配置解析为严格 `strong-etag`，不因升级自动降低写入保护。Koofr、Nextcloud、自定义地址和旧连接继续要求强 ETag 条件能力。首次合并确认页提示坚果云模式没有服务端原子比较写入：同一 `deviceId` 被多个实例并发使用时仍可能覆盖。正常多设备有各自的快照路径，同一配置文件使用 Web Locks。

Obsidian 参考调研记录在 [SYNC-WEBDAV.md](./SYNC-WEBDAV.md)：Remotely Save 通过上次同步状态、时间/大小和普通覆盖写处理 WebDAV；Cloud WebDAV Sync 采用不可变 SHA-256 Blob/Commit 与受保护的 HEAD，不过其当前策略仍要求强 HEAD ETag。Orinui 未改快照或加密 schema。

### 坚果云 PUT 回执缺少 ETag（历史严格模式处理，2026-10-14）

本节记录的强 ETag 补查逻辑后来经用户在坚果云实测仍无法取得 ETag；当前采用的坚果云兼容方案见上一节。其他 WebDAV 模板仍使用本节的严格策略。

用户报告条件探测对象 PUT 回执没有有效强 ETag，后续也报告 `DAV:getetag` 查询不到有效强 ETag。现在写入回执缺少有效强 ETag 时，适配器先查询目标资源的 `DAV:getetag`；属性缺失或无效时读取 GET 响应的 ETag。任一来源取得强版本后，继续以该版本发送 `If-Match` GET，并逐字节核对写入内容；版本变化、内容不符或 GET 也未提供强 ETag 时仍明确失败。该逻辑用于条件探测、媒体/快照发布及新库描述创建。普通 GET 无有效强 ETag 时也可由 DAV 属性或 GET 响应取得候选版本，并执行条件回读核验。RFC 4918 将 `DAV:getetag` 定义为 GET 表示所对应的 ETag 属性，具体支持仍以该服务器实测为准（[RFC 4918 §15.6](https://datatracker.ietf.org/doc/html/rfc4918#section-15.6)）。

新增适配器用例覆盖 PUT 回执缺失/弱 ETag、DAV 属性强 ETag、属性缺失后 GET 强 ETag，以及两种来源都无法提供强 ETag 时明确失败，并检查 If-Match 回读与最终清理。每次条件检查改用唯一探测路径，避免既有失败对象阻塞重试；旧错误路径中的诊断对象仍可能在云端，按完整相对路径确认后可手动删除。RFC 规范依据见上文。`pnpm compile`、`pnpm build` 与 `git diff --check` 通过；产物 `.output/chrome-mv3` 总计 1.04 MB，其中 JS 923.56 kB、CSS 102.99 kB，仍提示 JS chunk 超过 500 kB。按用户自行完成测试的安排不运行测试，坚果云实际服务复验待用户完成。

### WebDAV collection 创建返回 403（2026-10-14）

用户报告坚果云启用时创建 collection 返回 HTTP 403，原错误没有包含请求路径，因此无法确认当时被拒绝的是根路径还是子目录。代码检查发现 `prepareCollections` 原先把用户配置的 DAV 根 collection 也纳入 `MKCOL` 队列；流程现在先通过 `PROPFIND Depth: 0` 验证根路径为 collection，再只创建其下的 Orinui 子目录。应用子目录也会先查询，只有明确返回 404 才发送 MKCOL，以避免尝试重建现有目录。对 `MKCOL` 403 等失败状态继续明确报错，并显示被拒绝的 collection 路径；PROPFIND 错误也显示目标路径。坚果云官方帮助说明其他 WebDAV 客户端会在默认 `/dav/` 地址下自动创建应用目录；据此，本实现将配置地址视为现成根 collection，并在启用时实际查询确认（[坚果云 WebDAV 帮助](https://help.jianguoyun.com/?tag=webdav)）。
